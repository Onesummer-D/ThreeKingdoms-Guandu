# 《三国·官渡之战》全国赛技术升级规格

**Version:** 0.1-draft  
**Status:** approved  
**Date:** 2026-09-29  
**Target build:** Unity 2022.3.62f3c1 Windows build  
**Competition deadline:** 2026-10-23 23:59:59（以参赛指南为准）

## 1. 目标

在现有单机剧情解谜游戏的基础上，完成一条可在比赛现场运行、可复核、可展示的全国赛技术升级链路：

```text
统一战局事件流
  ├─ 完整 RunRecord
  ├─ 三级响应式影像
  ├─ 动态战术复盘 / 战役绘卷
  ├─ 史官卡片与结局解释
  ├─ 公网多人军议邀约
  └─ 受约束 AI 史料助手
```

现有“本局回顾”和战绩报告继续保留。战绩报告负责分析与分享，战役绘卷负责按照真实记录播放战局过程，二者共同读取事件流。

## 2. 范围与不做事项

### 2.1 本期必须完成

- P1：事件协议、完整 RunRecord、版本迁移与旧存档兼容。
- P1：VisualDirector 的常态 / 警戒 / 危局三级视觉状态，并连接声音、镜头/界面扰动和场景元素。
- P1：以真实事件记录为数据源的战役绘卷，支持播放、暂停、逐步查看、关键节点跳转和结局原因解释。
- P1：10–15 张数据化史官卡与核心人物卡，带史实来源和史实/演绎边界。
- P2：公网多人军议邀约：主机创建会话，手机网页通过二维码加入，云端中继建议，Unity 收到后由主玩家确认。
- P2：统一事件协议的导出、校验和演示用诊断面板。
- 可选 AI：云端可部署的受约束史料助手，回答必须绑定本地知识包或明确来源；无依据时拒答或回退。

### 2.2 本期不作为必要验收条件

- 从零训练基础大模型。
- 依赖未准备好的专用 GPU、商业模型私有权重或不可复现的外部服务。
- 账号体系、社交关系、多人同步推进同一剧情、实时语音。
- 电影级 Timeline/Cinemachine 重构；镜头响应采用轻量级可控实现。

## 3. 用户与运行环境

| 角色 | 能做什么 | 运行环境 |
|---|---|---|
| 主玩家 | 开始战局、作出决策、确认或拒绝建议、查看绘卷 | Windows Unity build |
| 远程参谋 | 扫码加入、查看当前局面、提交选项和理由 | 手机浏览器 |
| 评委/讲解者 | 查看完整记录、播放绘卷、查看来源和诊断信息 | Windows build + 手机 |
| AI 史官 | 基于知识包回答当前节点的史实问题 | 云端 API 或本地部署模型 |

## 4. 功能需求

### FR-001 统一战局事件协议

系统应提供版本化事件模型。每条事件至少包含 `schemaVersion`、`runId`、`sequence`、`elapsedMs`、`eventType`、`nodeId`、`chapterIndex` 和可扩展 payload。

首期事件类型至少包括：

- `RunStarted`
- `NodeShown`
- `DecisionMade`
- `ResourceChanged`
- `MiniGameStarted`
- `MiniGameAction`
- `MiniGameCompleted`
- `AdvisorSuggested`
- `SceneStateChanged`
- `EndingReached`
- `RunCompleted`

事件必须能被导出为 JSON，并能按序重放或生成诊断摘要。

### FR-002 完整 RunRecord

`RunHistoryData` 应新增：

- `schemaVersion`、`runId`、`seed`、创建时间和活动时长；
- 主玩家与参谋参与者信息；
- 事件流；
- 小游戏轨迹摘要、尝试次数和结果；
- 结局 ID、结局原因、资源阈值和关键决策；
- `historicalAnchor`、`historicalDeviation` 和说明文本；
- 数据完整性标记和导出版本。

旧版记录必须可读取。无法补齐的字段使用明确的 `unknown`/默认值，不得破坏已有战绩报告。

### FR-003 三级响应式影像

VisualDirector 根据兵力、粮草、计策、风险和事件严重级别计算状态：

1. 常态：正常色调、稳定音量和无扰动。
2. 警戒：冷/暖色偏移、轻微暗角、紧张音色、轻微界面或镜头扰动。
3. 危局：高风险色调、短促警示音、明显但可读的镜头/界面反馈、对应场景元素激活。

状态转换必须可记录为 `SceneStateChanged`，并允许在复盘中展示。缺少音频或可选场景对象时必须安全降级为 UI 反馈。

### FR-004 动态战术复盘 / 战役绘卷

系统应从真实 RunRecord 生成复盘视图：

- 时间线展示节点、决策、小游戏、资源转折、参谋建议和结局；
- 支持播放、暂停、逐事件前进、跳转到关键节点；
- 显示玩家决策与结局原因的因果关系；
- 小游戏使用轨迹摘要或符号化动画展示，不伪装成未记录的逐帧回放；
- 与现有战绩报告共享数据，不重新开启一局游戏。

### FR-005 史官卡片

至少提供 10–15 张数据驱动卡片，覆盖关键史实节点、核心人物、粮道/乌巢、许攸、袁绍军结构、曹操后方支持等内容。每张卡至少包含：标题、正文、史料来源、史实边界、游戏演绎说明、适用节点。

### FR-006 公网多人军议邀约

系统应支持以下端到端流程：

1. Unity 主机向云端创建短期会话；
2. 生成带会话 ID 和签名/过期时间的二维码；
3. 手机网页读取当前战局快照和可选建议；
4. 参谋提交昵称、选项和理由；
5. 云端中继并防止重复提交/过期提交；
6. Unity 轮询或长连接收到建议；
7. 主玩家接受或拒绝，结果写入 RunRecord；
8. 网络失败、超时和断线回退到本地参谋流程。

本期不要求远程参谋直接推进主线，主玩家始终拥有最终决策权。

### FR-007 AI 史料助手

AI 史料助手应：

- 使用项目维护的史料知识包和节点上下文；
- 返回简短答案、来源编号、史实/游戏演绎标签；
- 对知识包外问题明确说明依据不足；
- 记录问题、命中文档和回答版本用于测试；
- 云端模型不可用时提供本地固定答案或检索结果回退。

允许在有训练数据和算力时增加 LoRA/指令微调，但微调不是本期验收前置条件；不得把从零训练基础模型列为交付承诺。

### FR-008 可验证演示与导出

系统应提供一条固定演示路径，能展示：三级状态、一个小游戏轨迹、一个分支结局、战役绘卷、史官卡、手机建议回传和 AI 来源回答。RunRecord 和事件流可导出为脱敏 JSON。

## 5. 非功能需求

### NFR-001 可复现

相同 `seed`、内容版本和用户决策应产生相同的事件顺序和结局判定；不可复现部分必须标注原因。

### NFR-002 稳定降级

云端不可用、AI 不可用、可选场景对象缺失时，游戏主线、战绩报告和本地参谋流程仍可运行。

### NFR-003 数据安全

会话使用短期 token、过期时间、最小化玩家信息和服务端输入校验；不上传不必要的本地存档和个人信息。

### NFR-004 可测试

每个功能必须有自动检查或明确的手工验收步骤。公网邀约必须完成“手机提交 → 云端中继 → Unity 收到 → 主玩家确认”的双设备测试。

### NFR-005 比赛可交付

Windows 构建可离线启动并运行核心剧情；公网功能和 AI 需要在演示环境下可用，同时保留离线回退说明。

## 6. 验收标准

| ID | 验收内容 | 通过条件 |
|---|---|---|
| AC-001 | 事件协议 | 一局运行导出事件 JSON，顺序、版本和关键 payload 完整 |
| AC-002 | RunRecord | 新旧记录均可加载，报告和绘卷都能读取新记录 |
| AC-003 | 视觉状态 | 三种状态可由资源/事件触发，声音、视觉和扰动至少各有一项实际变化 |
| AC-004 | 绘卷 | 能播放同一局真实事件，支持暂停、逐步前进和结局原因定位 |
| AC-005 | 史官卡 | 至少 10 张可访问，均有来源与史实边界 |
| AC-006 | 公网邀约 | 两台不同设备完成二维码加入、建议提交、Unity 接收和主玩家确认 |
| AC-007 | AI 史料 | 固定测试集至少 10 问，答案带来源或可靠回退；无依据问题不编造 |
| AC-008 | 故障回退 | 断网、云端超时、AI 不可用时主线和本地流程仍可继续 |
| AC-009 | 比赛演示 | 从启动到完整演示路径不依赖编辑器脚本或人工改数据 |

## 7. 风险与决策

| 风险 | 处理方式 |
|---|---|
| 云服务器域名、TLS、端口或部署权限未准备 | 第 1 天列为阻塞项；先用临时 HTTPS/测试域名完成接口联调 |
| Unity WebSocket/轮询接入不稳定 | 先实现 HTTPS 短轮询，稳定后再考虑长连接 |
| AI 模型部署和微调耗时 | 先交付 RAG/固定知识包；微调设为可插拔增强 |
| 新事件字段破坏旧存档 | schemaVersion + 显式迁移 + 旧数据回归测试 |
| 视觉状态在场景对象缺失时异常 | 所有可选引用为空安全，保留 UI 反馈 |
| 公网功能未按时闭环 | 第 15 天设硬门槛，失败则冻结公网范围并保留本地回退 |
