# 阶段二验收总结：五幕剧情回顾

日期：2026-08-30

## 阶段目标

将原本把 200+ 个底层节点全部铺开的“战役全景图”，改造成玩家可以快速读懂的剧情回顾界面。回顾界面服务于叙事理解，不暴露底层节点拓扑。

## 本阶段完成内容

1. **五幕剧情聚合**
   - 将官渡之战划分为“两军对峙、官渡相持、许攸夜访、奇袭部署、乌巢决断”五个宏观阶段。
   - 每幕只保留代表图片、幕标题、时间地点短标题和一行剧情摘要。
   - 章节摘要由人工提炼，避免直接把长段落塞进 UI。

2. **按当前进度显示**
   - 当前章节依据 `DialogueSystem.CurrentNode` 判断，不再通过宽泛的节点 ID 区间误判未来章节。
   - 未进入的章节完全隐藏。
   - 当前章节显示“正在经历”，进入下一幕后，上一幕显示为“已完成”摘要卡。

3. **进行中卡片与完成汇总**
   - 当前章节可随关键节点追加“战况片段”卡片。
   - 各条结局解锁后的连续叙事保留一至两张代表性片段卡片，避免解锁提示与终局之间出现信息断层。
   - 进入下一幕后，上一幕不再堆叠所有片段，自动回到一张凝练的章节卡。
   - 结局卡片在实际抵达终局或 IF/史实结局解锁提示节点后显示，避免必须再点过空白终止节点才出现。
   - 结局卡片与普通剧情卡片共用同一行布局和节点背景图；若终止节点没有背景图或仍是通用“失败if”占位图，则依次使用对应解锁节点、已访问的战况节点或本幕代表图像，不提前显示未访问内容。
   - 史实胜利终点 `500217` 已改用既有“火烧官渡2”背景，避免胜利结局误显示失败氛围。
   - 章节、战况、结局卡统一卡高与步距，结局前后不再出现独立的大空白段。

4. **关键选择可读化**
   - 每个章节只展示锚点决策，不展示 200 多个节点连线。
   - 选项改为短标签，如“发石车”“地道奇袭”“坚守官渡”。
   - 选项状态与文字合并为单行，例如“已选择 · 坚守官渡”或“未探索 · 发石车”，避免状态文字和选项文字分离造成大片空白。

5. **运行时字体与布局适配**
   - 动态生成的 TMP 文本统一加载项目中文字体 `SC-Regular SDF` 及其材质。
   - 字号参考正文 `180`、父物体缩放 `0.25` 的实际视觉效果重新调整。
   - 主卡片标题与战况片段采用同一字号层级，选项状态标签放大并保持单行。
   - 卡片和按钮采用锚点布局，兼顾 1920×1080 与 1366×768。
   - “剧情回顾”入口移动到对话框左上方空白区域，颜色改为与对话框装饰接近的棕色。

## 相比阶段一新增的创新点

### 1. 从“节点图”变成“叙事回顾媒介”

阶段一的节点图主要用于开发者检查路径，信息量大但玩家难以阅读。阶段二把同一套数据重新组织为图像、标题和一句话摘要，让玩家即使忘记具体操作，也能快速串起官渡战役的因果链。

### 2. 进度驱动的渐进式叙事

回顾界面不一次展示全部内容，而是随着玩家推进逐步出现。当前幕保留过程感，完成后自动压缩成结果摘要，兼顾探索感和信息密度。

### 3. 选择结果的可视化反馈

关键选项被转化为短标签，并区分“已选择、未探索”。玩家可以一眼看出本局走过的路线和仍然存在的重玩空间。

### 4. 数据驱动、可扩展的章节配置

章节标题、摘要、代表图片、锚点节点和战况片段节点集中配置在 `CampaignMapUI` 中，剧情数据仍由现有 ScriptableObject 提供。后续增加章节或替换素材时，不需要重写回顾系统。

### 5. 面向实际展示的 UI 适配

本阶段不再把界面当作开发调试工具，而是按参赛演示和玩家阅读场景处理字体、间距、按钮位置、图片比例和屏幕适配。

## 阶段二自检结论

阶段二的“剧情回顾聚合版”目标已完成，当前没有影响展示的结构性缺项。以下内容属于优化报告中的后续阶段，不作为阶段二阻断项：

- 《三国志》史官注与史实对照模式
- 多周目“历史回响”与隐藏剧情
- 战术小游戏统一沙盘和复盘动画
   - 结局后的雷达图、时间轴和历史相似度
- 社交分享、扫码分支体验
- 水印、素材授权和投稿构建封板

## 当前验收方式

- 在 Unity 中重新编译脚本。
- 从“开始游戏”重新运行，确认第一幕时只出现第一幕卡片。
- 推进第一幕，确认新的战况片段卡片追加。
- 进入第二幕后，确认第一幕收拢为一张已完成摘要卡。
   - 检查“剧情回顾”按钮位于对话框左上方，且文字、字号和选项标签清晰可读；进入终局后对话框隐藏，按钮仍可用。
