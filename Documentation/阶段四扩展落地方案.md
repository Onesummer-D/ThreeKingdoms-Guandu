# 官渡之战 · 阶段四扩展落地方案

日期：2026-09-04

本文区分本次已修改代码、后续开发安排与暂缓内容，不代表所有功能已经完成。阶段一至三沿用已验收成果；阶段四按批次交付，每批保留实机审查停点。

## 一、项目的核心体验

玩家以曹操身份完成一场约十几分钟的互动战役，关键决策影响资源和七条结局线。可以独自游玩，也可以在犹豫时邀请朋友出谋划策。结局后，回顾“发生了什么”，战绩报告回答“我怎样作出了这些决定”。文化卡说明哪些来自史书，哪些属于创作。

10～15 分钟暂作目标体验时长，需以真实路线测试校准；不要在玩法介绍中把它写成所有玩家都能达到的保证。现有隐藏内容是彩蛋与称号，不把尚未存在的“隐藏菜单”写成卖点。

## 二、三个身份如何处理

当前实现固定曹操主将视角，增加新局前身份说明。玩家做的是曹军资源和部署决策，现有对白、小游戏和结局均依赖这套视角。

- 曹操：玩家扮演的主将，负责最后拍板。
- 许攸、袁绍：先进入“人物介绍”，介绍游戏中的动机、性格表现和所处阵营；有关史实另列来源，不将游戏性格标签当作客观历史定论。
- 受邀朋友：以自选昵称的参谋参与，不要求扮演特定历史人物，不挤占或接管主将操作。

不在本轮提供“选择袁绍却仍然替曹操出兵”的假身份切换。真正的三视角模式需要阵营资源、专属信息、对白、胜负条件和多轮回归，应作为后续扩展篇，而不是首页增加三个按钮。

## 三、分批交付顺序

| 批次 | 内容 | 明确停点 |
|---|---|---|
| 4A 第一批，本次 | 邀请卡可读性、完整文字邀请、开局身份说明、锚点幕次修复 | 编译与逻辑验证后检查 Unity 画面 |
| 4A 第二批，下一步 | 查看存档、手动保存、自动检查点、结局归档；关于游戏、人物/玩法介绍；基础设置 | 关闭进程后读档继续，关键数据一致 |
| 4B | 决策与资源日志、战绩报告、七结局评价、可保存的 PNG 海报 | 用真实一局生成报告，图表可追溯，图片可打开 |
| 4C | 轻量邀约闭环，先验证建议提交/采纳，再接手机网页与服务 | 两台真实设备完成邀请到报告；断网仍能单人继续 |
| 4D | 汇总文化深化、出处审核与全流程回归 | 五锚点、七结局、彩蛋检查完整；联机/离线均不漏内容 |
| 5 | 比赛展示片、四张宣传图、Windows 打包、素材与提交格式检查 | 可交付参赛材料 |

文化深化从 4A 的人物介绍、4B 的结局解释就同步开展，4D 做汇总验收，不拖到演示视频之后。本轮不把全部批次一次写完。

## 四、首页与局内入口

首页主要入口为“开始游戏”“查看存档”“关于游戏”。角落放设置图标；没有真实社区地址前不放可点击却无功能的社区图标。

“关于游戏”采用左右两张可点击卡片：人物介绍、玩法介绍。人物介绍内部再选择曹操、许攸、袁绍。玩法页说明七结局、彩蛋、资源影响、史实与架空区分、保存方式、单人也可完成，以及邀请的实际使用流程。

局内保留剧情回顾，在统一菜单提供保存与设置，避免新按钮叠满资源区。终局提供“返回主菜单”“本局复盘”“战绩报告”，样式复用现有浅色卷轴按钮，空间不足则两行排列。

设置首批做主音量、音乐、音效、窗口/全屏与文字显示偏好，保存到本地。现有侧边音量条迁移后不保留两个相互冲突的入口。亮度必须有真实视觉效果和恢复默认；画质档只在实际可调的渲染项目存在时添加，不给静态图项目摆空控件。账号资料待真实账号系统存在再做。

## 五、存档是下一步优先项

首版采用本地存档，不依赖注册或网络。建议三个手动槽、一个自动检查点、七类结局档案。手动覆盖须确认；自动保存不能覆盖手动槽。

每个运行存档至少记录：格式版本、剧情数据版本、本局 ID、保存时间、当前安全节点、已访问节点顺序、选项索引、四项资源、小游戏结果、彩蛋/结局状态、累计有效游玩时长，以及以后新增的军议记录。图片引用保存稳定 ID，不把 Unity 对象直接写进 JSON。

读档由统一恢复入口执行，先验证数据再恢复界面；不能简单跳到节点后又重复扣选项资源。读档后回顾、按钮、背景、资源和结局状态都必须一致。损坏或版本不兼容时说明原因并保留原文件，写盘采用临时文件和备份替换。

“任何时候想保存”保留操作意图，但小游戏中、转场动画中尚未完成状态时，显示“将在本段结束后保存”。需要离开时明确提示最近安全检查点，不能显示“保存成功”却丢失这一段。首版不承诺恢复到拼图移动一半或动画某一帧。

抵达结局后自动创建“通关结局 X：名称”归档。内部保留七种稳定结局 ID，并保留现有“史实结局 / IF 线 1～6”的命名，避免把 IF 线 1 误认为全作第一个结局。相同结局重玩不悄悄覆盖唯一手动存档。

验收至少覆盖：退出程序重开、每幕保存、小游戏前后、七结局、彩蛋、重复读档不重复扣资源、新局不继承旧局数据、损坏档提示与覆盖确认。

## 六、战绩报告与分享

复盘保留剧情卡；战绩报告复用同一套真实运行日志，不复制另一套结局判定。

报告包含：结局名称与图片、对应七结局评价、已发生的每次决策、兵力/粮草/计策/风险随节点变化的四条趋势线、关键变化原因、朋友建议与采纳记录，以及史官的简短解释。只显示本局实际经历的数据；早期失败不得补画未经历的后三幕。

玩家画像先做可解释的“本局决策倾向”，例如依据已选方案的明确标签概括倾向，并给出实际选择作为依据。它不是心理诊断。不伪造玩家百分位、全国排名、通关概率，也不靠最后四项资源画一个看似科学但无依据的人格雷达图。

“分享海报”首版导出真实 PNG，由玩家自己发送微信或其他平台；无需游戏上线。默认不带个人账号、设备信息或文件路径，可允许隐藏结局文字防剧透。只有真实试玩/邀请网页部署后才加入指向它的二维码；保存图片不等于已经发布到社交平台。

## 七、邀约采用异步参谋制

这里的“异步”表示不要求所有人同时在线跑完整局。朋友提交建议和主将读取建议仍需要能访问服务；不把离线说成能自动传消息。

1. 主玩家在尚未提交的决策点发起邀请，选择公开给朋友的战局信息。
2. 生成指向手机访客页的私密链接或真实可查的房间码，朋友不必安装完整 Unity 游戏。
3. 朋友看到这一刻的局势、已知选项和资源，用昵称选择建议并写一句理由。单个会话最多两名参谋；没有人加入也正常游玩。
4. 主玩家看到“谁建议什么”，可以采纳、另选或撤销邀请。采纳只是帮助选择，实际推进仍走原有游戏选项逻辑，确保资源、小游戏和结局判定只执行一次。
5. 双方贡献进入存档、复盘与报告。例如“参谋建议坚守，主将采纳，随后粮草变化……”。这一步完成后才有可验证的共创记录。

邀请绑定本局 ID、决策节点和状态版本。主将已继续、读档或新开一局后，旧建议不能改变当前局。服务处理重复提交、过期、撤销和断线重试；主将凭证与访客凭证分开，短码不能直接授权修改主将状态。只传必要战局信息，不上传完整存档和未访问分支。

首版不做内置实时聊天：选项、短理由和“采纳/未采纳”反馈已足够，讨论可以在微信继续。这样既能邀请亲友，也能把邀请发给已有群里的玩家；暂不提供陌生人自动匹配。

当前过渡版仅能复制完整文本、人工转发并参考朋友回复，还没有建议回传或贡献记录。它是可用的分享辅助，不应宣称已完成全国赛所需的邀约式闭环。

### 等待与倒计时

默认不因为邀请无人接受而惩罚资源。玩家随时可以自己决定；邀请可到期失效，不能把游戏锁住。五分钟可以作为可调整的邀请有效期候选，不当作强制罚时。

以后如做“战场压力模式”，应由玩家主动开启。倒计时、临近结束提示、减弱闪烁、声音开关和明确的扣减上限须一起实现；设置、史官注、后台切换和加载时暂停。本轮不加入持续扣粮或突然报警。

## 八、什么需要上线

| 功能 | 是否需要公网服务 |
|---|---|
| 单机、存档、人物/玩法介绍、设置、报告、保存海报 | 不需要 |
| 复制战局文本、朋友在微信回复 | 不需要游戏服务器；聊天发生在微信 |
| 手机网页看战局并提交建议，电脑端自动收到 | 需要部署网页和建议服务；不要求先上架完整游戏 |
| 二维码打开试玩或下载 | 需要真实可访问页面；Windows 构建不能直接当手机游戏运行 |
| 自动发布到特定社交平台 | 另需该平台接口与授权；本轮只保存和复制 |
| 玩家注册、社区动态、评分、晒图、实时聊天、匹配 | 需要持续后端、存储、安全与内容管理；本轮暂缓 |

在私有测试服务上可以先做两台设备的真实测试。正式公网部署前再确定托管位置、预算、域名、数据保留和隐私告知；本次没有购买、注册或发布任何服务。

## 九、文化信息不会丢

文化卡按“出处—原文/译述—创作理解—改编边界”组织。五个关键节点分别检查相持与兵粮、荀彧劝守、许攸来投、奇袭部署、乌巢与战后处置；七结局尤其要标明哪些是架空。彩蛋的“政治家的胸怀”关联到焚书信故事时，注明来源及游戏赋予的评价，不当成史书原有称号。

逐条核对版本、篇章和语境，不把演义与正史混引，也不把我们的战略解释放进引号冒充原文。来源较长时允许打开详情滚动阅读，不能为了单行漂亮截掉关键出处。原文审核和素材授权表都属于交付项；水印背景按此前要求暂不更换，但授权检查继续保留。

## 十、官方案例与取舍依据

- [Jackbox 官方加入说明](https://support.jackboxgames.com/hc/en-us/articles/15794759479959-How-do-I-join-a-game)：玩家可通过手机等设备的浏览器输入房间码和昵称。借鉴访客低门槛，不能省掉背后的真实连接服务。
- [万代南梦宫《棉兰号》多人模式说明](https://en.bandainamcoent.eu/the-dark-pictures/news/dont-play-alone-share-the-scares-newly-unveiled-man-of-medan-multiplayer)：单人之外分别提供双人在线与本地轮流模式，行动会影响故事并进入结算。借鉴参与可选、贡献可回看；本项目当前不承担全角色同步剧情的制作规模。
- [Steamworks 社区文档](https://partner.steamgames.com/doc/features/community)：社区是围绕真实玩家内容构建的产品能力。借鉴分享与讨论的目的，不在本轮复刻社区平台。

上述实现取舍是针对本项目现有代码和制作规模的判断，并不代表采用这些机制即可保证获奖。
