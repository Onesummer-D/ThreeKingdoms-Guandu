# 阶段三：响应式影像垂直切片

日期：2026-08-30

状态：已完成（2026-09-01 用户实机验收通过）

## 阶段定位

阶段三是把现有的“四维资源数值”转成玩家能直接感知的影像反馈。它对应优化报告中的 P1「VisualDirector」，也是项目从“有数据的剧情游戏”走向“数据驱动影像”的第一步。

本阶段拆成三个可验收停点：

- **3A 响应式影像垂直切片**：资源变化驱动画面氛围与资源文字状态。本次完成。
- **3B 史官注首批**：五个关键锚点的史实原文、白话释义和游戏改编说明。
- **3C 回归与展示封板**：验证不同资源状态产生可见差异，并整理演示录屏与缺陷清单。本阶段已完成。

## 3A 已完成

### 1. 新增独立 VisualDirector

新增 `Assets/Scripts/Managers/VisualDirector.cs`，运行时由 `FinalUIManager` 自动创建和初始化。VisualDirector 只订阅 `ResourceManager.OnResourceChanged` 与剧情节点显示事件，不写回剧情节点、不修改资源值，保持现有 ScriptableObject 架构可复用。

### 2. 四维资源状态映射

- 兵力、粮草偏低：画面加入轻微冷色压力感。
- 风险偏高：画面加入朱砂色危险氛围与边缘晕染。
- 计策偏高：保留很弱的暖金色提示，避免遮挡正文。
- 资源处于正常区间：效果自动回落，不持续污染原始美术。

状态采用连续插值而非二值开关，资源刚变化时过渡约 0.3 秒，节点切换时约 0.55 秒。

### 3. 资源数字可读反馈

资源数值会根据当前状态改变提示色，资源变化时对应数字轻微放大脉冲。该反馈不依赖新素材，也不覆盖对话、选项和剧情回顾按钮。

### 4. 无外部素材依赖

边缘晕染纹理由运行时生成的轻量渐变纹理提供，不引入第三方 Shader、插件或网络服务，保证离线运行和投稿包可迁移。

## 本轮增量：可见反馈与彩蛋回顾

上一版 3A 的常驻色调过于克制，实机观察时不容易确认“资源变化确实驱动了画面”。本轮保留常驻氛围的渐变逻辑，同时增加了资源事件闪变：资源下降/风险上升触发短促朱砂红闪变，资源恢复/计策提升触发暖金闪变，持续约 0.68 秒后自动回落；对应资源数字的脉冲幅度也提高，便于录屏中识别因果关系。

第五幕回顾列表新增彩蛋节点 500215。该节点访问后会生成一张与其他战况卡同尺寸、同排版的关键片段卡，直接使用“政治家的胸怀”彩蛋界面的战场背景图，不复用成就徽章图，避免卡片样式跳变。

终局时第五幕仍会先生成已完成摘要，并保留最后两张代表性战况卡。这样彩蛋触发或终局前的关键片段不会在进入结局后突然消失，结局卡紧接其后，形成“战况 → 收束 → 结局”的连续阅读顺序。

“剧情回顾”入口增加显式生命周期控制：返回主菜单时强制隐藏，开始新局时恢复；不再依赖 `CloseMap()` 的默认行为猜测当前界面状态。

## 本轮增量：终局复盘总结

终局画面不再显示普通的“剧情回顾”入口，避免玩家误以为仍处于普通游玩状态。程序会运行时克隆原有“返回主菜单”按钮，生成同款式、同字体和同悬停反馈的“本局复盘”按钮，并放置在主菜单按钮下方。这样终局保留两个清晰动作：离开本局，或查看本局经历。

“本局复盘”沿用卡片式剧情回顾界面，但增加了终局专属信息层：每个已完成章节摘要底部显示“本局选择：发石车/地道奇袭/诈败埋伏”等实际选择；终局前的代表性战况、结局卡和结局图片按顺序连续呈现；最后追加“本局复盘 · 总体评价”卡。七条结局线分别配置独立评价文案，评价只在玩家真正抵达对应结局后出现。

复盘模式仍由已访问节点集合驱动，不会因为打开终局界面而提前创建未经历的章节或分支。关闭复盘时，普通入口不会错误复活，专属终局复盘按钮会恢复；点击“返回主菜单”或重新开始时，两个终局按钮都会清理。

## 3B 已完成：史官注首批

在五个决策锚点（1001、2001、3001、4001、5001）的章节卡上增加“史官注”按钮。按钮只在对应锚点已经访问后出现，继续遵守阶段二建立的“未到达不显示”原则。

史官注采用独立运行时弹层，不改动原有剧情数据。每个锚点固定提供四个字段：参考来源、史书记载、今天如何理解、游戏改编说明。首批内容以《三国志·魏书·武帝纪》的通行译述为主，对乌巢奇袭等后世整理内容明确标注，方便后续补充正式引文和校注。

弹层关闭后回到原回顾面板，选择状态、已访问节点和滚动内容不被重置。普通剧情回顾和终局“本局复盘”均可打开史官注，玩家可以在历史信息和自己走过的路线之间来回对照。

静态验收结果为：五个史官注锚点全部映射，七条结局评价全部保留，终局普通入口隐藏与新局恢复逻辑存在，史官注不写入剧情数据，三个改动脚本通过 Unity Roslyn 编译。展示封板阶段还需在 1920×1080 下确认弹层文字换行、按钮位置、回顾滚动和红/金资源闪变强度。

## 3B 可读性微调：史官注字号与标题层级

根据实机观察，史官注弹层原先字号偏小，且三个分区标题与正文共用同一个 TMP 文本对象。本轮将“史官注”主标题提升到 64 号，来源行提升到 30 号，正文提升到 36 号；“史书记载”“今天如何理解”“游戏改编说明”拆为独立标题控件，统一使用暖金色 44 号，正文保持浅色 36 号。这样三个分区标题在视觉上明显大于下方正文，也避免富文本拼接造成的对齐和换行问题。

代码级验证已通过，实际 1920×1080 换行和最终观感仍需在 Unity Game 视图中复核。

## 2026-08-31：回顾同步与改编说明换行修复

复核发现，剧情回顾原先只用 `CurrentNode.nodeId` 判定当前幕。进入小游戏或特殊过渡节点时，当前节点可能短暂保持在上一幕，导致玩家已经到第四幕时回顾暂时只显示第一幕。现改为同时扫描本局 `visitedNodeIds`，以“当前节点幕次”和“已访问节点最高幕次”中的较大值作为回顾范围；面板打开期间还会监测访问数量与当前节点变化，必要时自动重建，避免等待后续场景才同步。

史官注的“游戏改编说明”长句改为单行自适应字号，字号范围为 36 至 26。文本优先缩小保持一行，极端超长时才触发省略保护，避免出现第二行只有一个字的视觉断裂。

本轮改动未触碰对白节点、资源数值或 ScriptableObject 数据；Unity 2022.3 Roslyn 编译检查通过，实际转场时序和不同分辨率下的观感仍需在 Game 视图复核。

## 验收标准

- 选择导致资源下降后，2 秒内能看到画面氛围和对应资源数字变化。
- 资源恢复后，颜色和晕染能平滑回落。
- 效果不遮挡对白、选项、资源 HUD 和“剧情回顾”入口。
- 进入小游戏、结局和重新开始流程时，不改变原有剧情逻辑；重新开始会刷新视觉状态。
- 同一套代码在资源数值不同的两次运行中产生可复现的视觉差异。
