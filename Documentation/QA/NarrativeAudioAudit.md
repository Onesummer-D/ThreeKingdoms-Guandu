# 《三国·官渡之战》全剧情音效梳理与补录清单

**审查对象**：`Assets/Scripts/Data/GuanduDialogueData.asset` 中全部 204 个剧情/选择/结局节点；`AudioManager`、`DialogueSystem`、`FinalUIManager` 的事件播放路径；现有 `Assets/Audio/` 声音素材与场景引用。

**重要定义**：`sfxOnEnter` 是**进入剧情节点时的单次音效**。没有这个绑定不代表节点完全无声——背景音乐、小游戏、UI 点击、动态战况等也各有音频通道。不能简单把 204 个节点的无 SFX 都判为错误。优先设计战场动作、信息转折和画面强提示音，不对连续文字节点机械地逐句配音。

**注意：** 音频开头低电平时间若接近整个时长，仅表示这一次 −45 dBFS 门限检测在大部分时段认为声音很小；不等于“整个文件完全静音”，也不等于已经主观听不见。须先用耳机/波形工具复核有效瞬态、编码与播放延时。我们目前**没有直接修改原始 OGG/MP3 音频数据**，以免在没有监听审核时剪坏素材。

建议音频制作的处理顺序：**检查波形/起音 → 清理无用前导静音 → 统一响度与保留峰值余量 → 导回 Unity 听感对照 → 检查不同音量设置下 BGM Ducking**。可在 `SoundAssetLevelAudit.js` 重新跑一致的源文件测量。

## 其它已发现的工程问题与边界

1. **火烧乌巢音效错绑**：原场景 `AudioManager.fireWuchaoSFX` 错误引用 `箭矢破空音.ogg`。目前代码没有直接调用这个字段，因此主要属于**错误资源引用风险**，并非已证明的当前播放错误；已清空引用，等合适的纯燃烧音效补上。`bgmFireWuchao` 指向 `火烧乌巢.ogg`，动画已有 `FinalUIManager` 的专属 BGM 调用，保留不变。
2. **史实胜利配乐定位需文案确认**：`DialogueSystem.GetAutoBGM` 对 500200～500308 使用“战争背景音”，所以 500211/500217 史实胜利段**不会自动切换**“剧情点五-胜利”曲（后者目前用于 500407～500413）。这是当前实现的明确规则，但不能擅自确定为错；文案/音频组需要讨论：史实胜利是否应在 500211 起加入胜利旋律？要避免与 500215 成就音效冲突。
3. **音量是听感问题**：即使代码将单次播放增益提升到合理水平，原始音频的响度（LUFS）、动态范围、峰值与是否存在大量空白，仍须音频工具实际测量、必要时做统一母带处理。
4. **素材授权未闭环**：仓库 `Documentation/素材授权台账.md` 说明大部分 BGM / SFX 来源和再分发许可尚待补齐。新绑定不改变素材的版权许可状态；发布/参赛前仍需逐条核验。
5. **音效密度不等于质量**：对于长段对话、信息解释、艰难抉择和死寂场面，保留安静是设计选择；“未绑定”不等于“必须填充”。
