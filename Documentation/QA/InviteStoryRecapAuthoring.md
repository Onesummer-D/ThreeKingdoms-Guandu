# 军议邀约：事件驱动的“已走剧情”摘要

此文件说明新的**严格无剧透**回顾机制。专用于“军议邀约”（含发往公网参谋网页的战局快照），不改变“剧情回顾／战役绘卷”现有的五幕摘要展示。

## 当前实现

- 配置：`Assets/Resources/StoryRecap/InviteEvents.json`，Unity 在运行时用 `Resources.Load<TextAsset>` 加载。
- 实现：`Assets/Scripts/UI/InviteStoryRecapBuilder.cs`；入口：`CampaignMapUI.TryBuildInviteSnapshot()`。
- 首批内容：**29条短事件卡片**，其中包含五幕基础场景和各分支的重要**已发生事实**。这些是依据现有游戏剧本编写的**技术验证草稿**，尚未由文案组润色/审定。
- 使用 `DialogueSystem.visitedNodeOrder` 恢复实际游玩顺序。**只解锁已经访问过的事件节点，并且当前正在显示的节点不纳入回顾**：当前问题和选项会由“正在考虑”栏独立显示。既不会按“已到某幕”直接插入整幕预设文本，也不调用 API／DeepSeek 生成新事实。
- 同一节点被重复打开不会重复拼接事件；改选不同分支不会提前出现未访问分支内容。新一局不复用旧一局的回顾结果，读档由 `DialogueSystem.RestoreRunState` 恢复已访问的节点顺序。
- 已完成的章节保留**最早一条已发生事实 + 最近两条**，目前最后到达的一幕则保留**最早一条 + 最近三条**（不够则全部保留），按五幕顺序拼成可读文本，避免长文章占满小屏幕。
- 只输出客观事实，不给尚未决定的选项写“好处／坏处／正确答案”，也不把游戏架空的结局说成史书记载。若还没有已结束的关键事件，显示“暂无已走剧情”。

## 文案组如何接手：无须另写30篇

文案组仍可以**优先完成 AI 史官的史料知识库**，这部分不必同时赶工。

这次我已按现有剧本拟好29条待审短稿，并把事件与解锁节点绑定。文案组只需要：
1. 修改五幕基础事件的措辞（ID A01、B01、C01、D01、E01），与之前五条章节摘要保持统一口吻。
2. 有空时抽样审校其余24条，尤其第三幕“许攸夜访／处决”与第五幕 IF 分支是否客观、中立。
3. 如果某段确实写得不合适，**只需直接修改该条 `text`**；不要修改 `id`、`chapter`、`triggerNodeId`。新增事件时填独立ID，绑定必须指向确实已发生对应事实的剧情节点。

配置样例：

```json
{
  "id": "C04",
  "chapter": 3,
  "triggerNodeId": 300309,
  "text": "许攸向曹操透露袁军乌巢粮仓情报。"
}
```

这条**只有玩家实际进入并离开300309后**才能出现；如果当前仍在300309，或者走到了处决许攸但从未触达300309，就不会显示。

如文案组有既往正式剧情文字、Word/Markdown底稿，直接交给技术端即可按其既有用词、句长、视角修订这一套 `text`；技术端仍负责核对每句话与对应节点的事实一致，不能仅凭语言风格复写而剧透。

**注意“已走剧情”不等于“当前正在考虑的选项”：** 后者由现有 `snapshot.DecisionContext` 提供，允许客观展示当前已知问题及选项原文，但不在摘要里猜测选择结果。

## 测试要求

- 刚进第一幕，尚未越过第一关键节点时只显示“暂无已走剧情”，不能抢先讲土山箭雨、发石车。
- 第三幕看到许攸初至，不能提前出现“乌巢情报”；只有实际进入并离开300309才能出现。
- 走处决支线，已离开300408可以出现许攸遭处决；如果从未到过300309不能凭第三幕章节模板写“许攸献出乌巢情报”。
- 进入第五幕之前，不能出现“乌巢起火”；在500101刚显示时也不应提前加入摘要。
- IF6 弱兵力进攻不能拿另一个已胜利分支的战绩当回顾。
- 读档、进入新一局、重复访问同一节点、触发军议邀请、复制公网战局链接，回顾内容都要与实际已发生节点一致。
- 每条新文案都需要有可用的“先于此节点”、“此节点之后”、“其他分支”反例测试，以保证版本更新时仍然不剧透。

本机制追求**已有事实可验证**，而非向玩家剧透决策分支的潜在收益、路线结局和风险阈值。
