# 问史官聊天验收

## 启动
打开 `Assets/Scenes/Guanduuuu.unity` 并进入游戏。无需拖脚本、绑定对象或输入模型密钥，`FinalUIManager` 自动创建界面。游戏画面右侧显示用户提供的透明问史官图标。

## 实际操作验收
1. 点击图标：半透明窗打开，背景可见，剧情/小游戏暂停；点击窗口外不会推进剧情。
2. 输入“许攸带来了什么信息？”并点发送：有等待状态，出现回答；等待中不能重复发送。
3. 追问“那曹操为什么相信他？”：理解“他”指许攸；缺少证据的动机不能编造。
4. 点击来源：展开具体史料，再点击收起；长回答和记录能上下滚动。
5. 点击推荐问题：直接发送对应问题；空输入不能发送。
6. 中文输入法确认候选字不会误发；Enter 发送，Shift + Enter 换行，Escape 关闭。
7. 关闭后继续游戏；重新点开保留本局记录。等待中关闭再打开仍可收到结果。
8. 重新开局：旧记录清空。重置前请求不能把迟到结果插进新局。
9. 暂时断网：窗口显示本地史料摘录和来源，游戏仍能继续；知识包外问题说明依据不足。
10. 1920×1080、1280×720、1024×768 检查标题、推荐问题、输入与发送不相互遮挡。
11. 在开始一局但尚未通关时问“本局刚才做了哪些选择？”，确认返回的选择来自当前实际记录，**不提前出现结局名称**；点击“查看本局记录依据”应标示为游戏事件，而非《三国志》。
12. 完成一个 IF 分支后问“我为什么会输？”，应出现本局真正达到的结局、游戏给出的结局评价、相关实际选择及资源净变化；不能把模拟数值当成史实。用不同路线复测，避免沿用上一局数据。
13. 暂时断网再问“我为什么会输？”，本地应只使用当前有效记录简要回答；没有本局数据时说明无法判断。
14. 对史料问题“游戏复盘能证明古代战场的真实过程吗？”不得误进本局战绩分支；对“我为什么要听许攸的建议？”应仍作历史问答，而不是误认为询问本局输赢。


## 自动验证
固定史料题和后端合约见 `server/historian-ai/run-eval.js`、`chat-test.js`。Unity 命令行 QA 的入口为 `HistorianChatSmoke.Run`，须先运行工作区 `outputs/2026-10-14-historian-chat/mock-model-service.js`；无需 API Key，仅监听回环地址。测试启动真实场景，通过实际按钮事件和输入组件验证生命周期，并渲染场景 UI。测试输出位于同名 outputs 目录，测试服务仅生成合成问答。

相机渲染用于跨尺寸布局检查；真实中文输入法与鼠标体验应在 Game View 再点验。`HistorianChatSmoke.Preview` 可打开专用点验场景。显式 QA 入口会将测试存档隔离到工作区 `qa-saves`，不使用正常玩家存档目录。此次范围不含整局输赢分析或持久化跨重启聊天。
