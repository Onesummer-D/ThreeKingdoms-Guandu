## 执行顺序

1. **P0（已在 PR #16 分支修改）**：采用谨慎核校的新 H01–H10、保留 H11 地理，并扩展 H12–H15，D01 独立记录游戏边界；校正 UI “三项/四项资源”。
2. **P1（核心已在 PR #16 分支接入）**：10条范例只用于史官回答口吻，升级引用检索与离线回退。另20条扩展问答与测试题仍需分批对齐证据、避免错引。
3. **P2**：修订五幕史官注、13 张用户可读卡片、人物短传等；修订前核对是否已经进入结局/未解锁剧情。
4. **P3**：首页和邀约其余描述、海报、退出按钮等纯措辞微调；以 Unity 实机视觉验收为准。

## 约定

- 可修改的 **静态文案** 与不可随意更改的 **机制标签、服务地址、占位符和运行状态** 分开审核。
- 保留 `{n}`、`{title}`、`{choice}` 等程序占位符；保留 `[Hxx]` 的史料含义且要等迁移确认。
- 任何“历史事实”显示需要可定位到来源层级；**玩家本局选择**只能使用 [G01] 的记录，不可用史书给这局补写结局。

### 回归和验收边界

- 静态检查入口：`node Documentation/QA/HistorianPlayerCopyChecks.js`，在 PR CI 的 `Historian editorial intake review` 中运行。
- 应在 Unity Windows/移动端至少实测：第三幕未得情报→得情报后史官卡解锁；第五幕未焚粮→火攻后解锁；任何结局触发后“史实结局／战后余波”开放；旧存档中历史节点访问顺序仍有效；主页与出征之前的多行字不溢出。
- 「史官卡片」按剧情事件分段解锁 ≠ 玩家主动向 AI 询问历史。主动追问依旧允许有依据地讨论史实与反事实，但不得将结局或人物后事主动塞进无关回答。
- 未改变腾讯云服务端配置，`grounding-v4` 仍需部署后才能用线上响应核实。
- H01 数字估算、H06 裴注来源、H08 归降先后等史学争议**不能仅凭自动检查宣布已通过历史人工核校**。交稿 JSON 的 `pending_editorial_qa` 仍须保留。
