# 史官文案与问答口吻：2026-10-19 重构与人工验收

## 为什么要改

Unity 实机反馈发现两个独立问题：

1. **五幕史官注和13张卡片**虽然从文案组《校订稿》出发，但此前的接入稿沿用了“不是……而是……”“关键在于……”等抽象分析句，缺少让玩家记住的史书动作和具体出处。它们是 **C# 静态文本**，和 DeepSeek 完全无关。
2. **问史官聊天**已有文案组10组示范问答，但提示词截断示例、对表达形式约束过多；严格引用校验失败时直接把一两张史料卡摘要拼成答案。当前测试分支的这些更改**尚未部署腾讯云**，线上旧服务的回答不能作为新版质量验收依据。

## 本次已经进 PR #16 的修改

- 5幕史官注、13张玩家卡片共18个“今天如何理解”段落都改为**能指出具体人物、战事、史书篇目或记载差异**的表述。保留其“参考来源/史书记载/今天如何理解”功能区，不改变文字面板的布局。
- DeepSeek 提示词不再鼓励统一结构。按事实、原因、过程、比较、反事实、游戏机制区分回答方式。句首优先具体事实，减少空泛否定；分歧才说“谁记载了什么”，不套三段式。
- 一次仅选最相关的文案组示例供**语言风格参考**（最长390字），绝不把示例当证据引用；历史内容仍必须来自卡片所含原文/出处。
- 若模型的回答开头空泛回绝，或证据校验不合格，就带着校验原因**最多重写一次**；仍不合格则只使用最相关史料卡的可归属摘要，必要时补一张确实相关的卡，不再拼接大量无关材料。
- Unity 本地离线回退也只展示最相关的一张卡，去掉“（史书记载与边界）”等机械标签。
- 缩小“精确/准确/分钟”等拒绝关键词覆盖范围：问“如何准确理解许攸投曹”不该一律拒绝；只有需要逐日精确伤亡等未证数据时才回绝。
- **未取消安全边界**：禁止把游戏设定当历史；史料分歧要说明来源；不允许虚构精确数字、引文、许攸之死等剧透；保留 `[Hxx]` 合法性、逐句引用、史实矛盾与数字检查。

## 预期玩家体验（人工审核示例，不是已获得的在线模型输出）

**问：曹操为什么想退回许都？**

期望：曹操在官渡与袁绍相持，军粮快用尽，便写信给荀彧商量回许都。《荀彧传》记荀彧劝他坚守，还提出“先退者势屈”；曹操接受建议，继续守官渡。

不期望：现有史料无法证明退兵的具体原因。可能与运输和士气有关。至于他当时到底如何考虑，没有定论。

**问：许攸为什么投奔曹操？**

期望：《武帝纪》说许攸贪财，袁绍未能满足他；《后汉书·袁绍传》则记其家人犯法被审配拘系，许攸愤而离去。两种记载解释了不同的直接诱因，不能无凭据将它们合为同一事件。

**问：游戏里的发石车和地道真是三选一吗？**

期望：史书记载袁绍先架高橹、筑土山射击曹营，曹操造发石车击毁楼橹；袁军再掘地道，曹军挖长堑防御。这是一段攻守相继的过程。游戏把它们拆成选择，是为了让玩家亲自参与部署。

**问：曹操到底有多少兵？**

期望：《武帝纪》记“兵不满万”，《袁绍传》记袁绍“精卒十万、骑万匹”。裴松之质疑曹军不足万人的字面数字，因为曹操还能分营相抗。所以可以确定双方兵力悬殊，不能把“不到一万”直接当成精确统计。

**玩家可见的答案示例不附内部编号。** 程序内部可以利用证据索引完成引用校验，玩家点击「查看史料来源」时只显示具体书名、篇目和必要的出处说明；游戏规则及本局记录则使用独立的自然语言来源名称。

## 上线前必须人工验收

1. 先在 Unity 验收18段新文本的可读性与换行。未改文字框尺寸，需要特别注意长句是否溢出。
2. 以**测试服务端**调用真实 DeepSeek，记录至少20道历史问题：5道“为什么”、5道具体事实、4道史料分歧、3道游戏与史实区别、3道无证据/越界问题；保存原问题、答案、来源卡、模式（`grounded_model` / `grounded_fallback` / `grounded_refusal`）。
3. 人工标注每题“是否正面回答、包含几个可核实的新知识点、引用是否匹配、是否套三段式、是否越界剧透”；只看 HTTP 200 或合法编号，不算史学验收。
4. 检查网络断开时离线兜底是否自然且关联提问；真实对话多轮连续追问是否出现过量回绝。
5. 保留文案组尚未核定的 H01/H06/H08 历史争议标记；**不要因为 CI 通过就直接上线**。腾讯云更新后再确认服务端版本标识 `grounding-v4`。
