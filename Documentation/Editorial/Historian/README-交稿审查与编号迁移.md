# 《官渡之战》文案交稿：AI 史官与游戏 UI 接入前审阅记录

> 状态：**待核 / 暂不启用新数据**。本目录为 2026-10-19 收到的四份 Word 交稿的可审核结构化副本；不是正式上线知识库、也不意味着微调了模型。

## 四份交稿分别做什么

1. `官渡之战_AI史官史料知识库(1).docx`：H01–H10 史料依据，包含出处、引文、白话、历史边界和游戏关联。已原意转录到 `historian-corpus-intake.json`。
2. `官渡之战_AI史官示范问答(1).docx`：10 例史官口吻、提问场景、来源及事实/推断/演绎分层。已转录到 `historian-example-intake.json`。**示范答案只可用于回答风格学习或审核过的离线 FAQ，不能当作史料原文。**
3. `《官渡之战》文案组校订稿 (1).docx`：包含五幕史官注、13 则玩家可读史官卡片，并在附录额外给出 **13 张扩展史料表格、20 条问答、10 条测试题**。这是另一种更广的组织结构，**没有按新 H01–H10 一一编号**；本轮先审，不混入上述两个独立 JSON。
4. `文案组待改稿汇总(2).docx`：开场、五幕摘要、七结局、人物、邀约、海报、保存退出等 UI 文案。要用代码上的 **精确 UI 字符串与占位符对照**逐项实施，不能因为是一份“待改”文稿就直接替换所有现有代码（尤其 PR #12/#13/#15 改过的界面）。

## 需要文案组/史料核校的事项（合并正式知识库前）

1. **H02 自相矛盾**：主题写“生擒颜良”，所引《武帝纪》却是“击破，斩良”。确认改成“斩颜良”，不传播误记。
2. **H06 史料来源评价**：将《曹瞒传》称“吴人所作，立场偏曹”，这种因果归纳需要核实；应保留“裴注引杂史，细节需谨慎”的可靠层级，不推定其政治倾向。
3. **H01 兵力估算**：“史学界一般认为两三万以上”、裴注引《世语》的数量解释是超出正文直接记载的论断，请补准确出处；未核定前回答应说“兵力有争议”，避免把估算当作确定值。
4. **H07/H08/H09 的袭击、焚烧、降曹先后**：陈寿正文、裴注、《曹瞒传》与不同人物传记需分别标注，尤其 H08 已承认“因降而溃”与“因溃而降”有冲突。
5. **玩家界面 13 则卡片 vs 本库 10 张 H 卡 vs 校订稿附录 13 张资料表**：三个数量相似/名称近似的体系并不等价。建议使用独立命名 `UI-C01…C13`、`H01…H10`、`EX-H01…EX-H13`，在通过历史核校前不合并编号。
6. **新问答 10 例 vs 附录 20 条**：10 例可用于 few-shot 口吻或题型回归；20 条为扩展候选，需统一引用编号再加入运行知识库。
7. **“三项资源”与实际四项资源冲突**：旧文稿“游戏中的三项资源”和部分史官注仍沿用三项说法；当前游戏为兵力、粮草、计策、风险四项，任何玩家可见的总数描述需要校正。
8. **人物评论有事实与价值判断混杂**：例如“曹操：疑人不用，用人不疑”“袁绍：骄兵必败”是概括性人物评价，不是可引用的史料原句，应作为修辞或演绎标识。

## 接入技术路线（建议分两个独立 PR）

**第一轮（本 PR）只入库并审校**：记录原交稿、编号映射、测试基线和作者需复核项。CI 验证10条 H 卡、10组 Q&A、所有引用合法；**不改变生产检索/回答**。

**第二轮（核校通过后）**：
- 用新 `H01–H10` 替换服务端 `server/historian-ai/corpus.json`，同时同步 Unity 离线包 `Assets/Resources/Historian/corpus.json`。
- 更新 `eval.jsonl` / `chat-test.js` 中全部旧 H 编号预期，以免编号正确却引用别的事实。
- 在 `grounding.js` 中保留独立的 `[G01]` 战局复盘；新增“原文、原文出处、历史边界”作为引用依据，且不可把游戏操作、示范问答当作历史事实。
- 示例问答 **只提供口吻范例**；带精确史实的示范句仍须经过 H 卡验证。模型不可通过“套用答案”绕过逐句引用检查。
- 后端检索增加角色/事件检索门槛与误检抑制；H10 战后史实只在玩家明确询问结局时出现，减少主动剧透。
- 深度测试：10组示范问答 + 10条扩展测试题（包含来源层级/拒答/张郃传分歧）+ 现有 G01/HTTP 回归。历史准确性仍需人工评审，不能以静态测试通过冒充史实核验。
- 已合并代码不自动更新云端服务：部署后核验知识库版本和响应中实际 `citations` 与模型端配置。
